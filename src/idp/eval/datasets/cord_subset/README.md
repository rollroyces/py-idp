# CORD-subset eval dataset

A 5-receipt hand-curated subset modeled on the
[CORD: Consolidated Receipt Dataset](https://github.com/clovaai/cord)
shape (Park et al., 2019). Used as a reproducible public-dataset
benchmark for py-idp.

## Why this exists

The in-tree `invoices/` eval has only 3 documents and only tests the
`Invoice` schema. That's enough for a smoke test but too small to
characterize real-world accuracy.

CORD is the standard receipt-extraction benchmark in the literature.
Five hand-curated receipts cover the common shapes:

| file | shape | tests |
|---|---|---|
| `receipt-001.txt` | clean cafe receipt | baseline |
| `receipt-002.txt` | restaurant with tip | `tip_amount` arithmetic |
| `receipt-003.txt` | convenience store with OCR errors (l→1, O→0) | robustness to noisy text |
| `receipt-004.txt` | grocery with quantity > 1 | `LineItem` quantity math |
| `receipt-005.txt` | parking garage, no line items | `LineItem` empty-list path |

## How to expand

The CORD paper distributes ~1000 real receipts. If you want to evaluate
py-idp on the full dataset:

1. Download CORD from the official source (see `https://github.com/clovaai/cord`).
2. Convert each receipt's annotations to a `cases.jsonl` entry with
   `{doc_path, schema: "Receipt", gold: {...}}`. The `Receipt` schema in
   `idp.core.schemas` matches CORD's JSON structure.
3. Drop the docs in `docs/` and update the `cases.jsonl` indices.
4. Run:

   ```bash
   idp eval --dataset src/idp/eval/datasets/cord_subset \
            --strategy mock,mock-omits \
            --output cord-results.json
   ```

## Licensing note

CORD is distributed under its own license — review before redistributing
its documents. The 5 receipts in this directory are **synthesised** (not
copied from CORD); they exist to validate the schema and pipeline shape.
For real CORD benchmarks, download from the original source.

## Reproducing the numbers

The README's benchmark table is regenerated by:

```bash
python examples/benchmark_cord.py
```

This runs the in-tree MockBackend against all 5 receipts and prints
per-field precision / recall / F1, plus latency. No API key needed.
